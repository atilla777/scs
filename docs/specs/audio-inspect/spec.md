### 1. Основания и принятые решения

Подтверждённые решения:
- **D-01:** WAV PCM16 и float32; остальные форматы явно отклонять.
- **D-02:** настраиваемые порог тишины и минимальная длительность; defaults **−60 dBFS и 0,1 с**. Тишина сама по себе не ошибка.
- **D-03:** пики и интервалы тишины по каналам; дополнительно общий пик и одновременная тишина всех каналов. Без downmix.
- **D-04:** при NaN/Inf дочитать файл, подсчитать каждый вид и первую позицию по каналам; диагностический отказ, явные ограничения остальных измерений. Не заменять нулями и не считать тишиной.
- **D-06:** документированный **настраиваемый предел числа интервалов**; превышение означает неполный отчёт и неуспешный статус. Сканирование продолжается до EOF для полных пиков и счётчиков, кроме ошибки чтения или отмены. Численный default определяет дизайн.

Конечные float-значения за ±1 предложено измерять без ограничения амплитуды и без самостоятельного отказа inspect.

Остальные конкретизации ниже — предложения в составе полного кандидата, не ранее принятые требования.

### 2. Цель и границы

Потребитель — AI-агент или пользователь CLI. Цель — получить объективный машинный отчёт о существующем файле независимо от render.

Включены метаданные, sample peaks, тишина, нечисловые значения и целостность чтения. Исключены validate, сравнение с ожидаемыми параметрами, оценка допустимости клиппинга/тишины, RMS/LUFS/true peak, резкие границы, графики, воспроизведение, конверсия, ремонт и музыкальная оценка.

Основной сценарий: задать файл и параметры → проверить вход → обследовать данные → вернуть измерения, полноту и диагностику. При отказе доступные результаты явно ограничиваются; автоматического повтора нет.

### 3. Требования

**R-01. Вход.** Публичная операция `audio inspect` принимает один локальный файл. Абсолютные и относительные пути допустимы; последние разрешаются от рабочего каталога вызывающего процесса. Поддерживаются обычные файлы; symlink, stdin, FIFO и устройства явно отклоняются.

**R-02. Форматы.** Поддерживается little-endian RIFF/WAVE: signed PCM16 и IEEE float32, включая соответствующие WAVE_FORMAT_EXTENSIBLE subtype/valid bits. RF64, RIFX, compressed WAV, PCM другой разрядности, float64 и другие контейнеры явно отклоняются без конверсии. Расширение имени не доказывает формат.

**R-03. Метаданные.** Сообщаются контейнер, sample format, sample rate, каналы, декодированные frames и длительность `N/rate`. Frame содержит sample каждого канала. Rate и каналы положительны; ограничения render автоматически не наследуются. При неполном чтении заявленный объём отличается от обследованного; неизвестное не выдумывается.

**R-04. Пики.** Канальный sample peak — максимум `abs(sample)`; общий — максимум по всем каналам без усреднения. PCM16 нормализуется делением на 32768; float сохраняет исходный масштаб. Сообщаются линейный пик и `20·log10(peak)` dBFS. Амплитуда 1 соответствует **0 dBFS**; нулевая амплитуда — **−∞ dBFS**, с явным JSON-безопасным представлением, определяемым дизайном. Конечные значения за ±1 не обрезаются и сами по себе не означают отказ.

**R-05. Параметры тишины.** Принимаются конечный порог `T ≤ 0` dBFS и конечная длительность `D ≥ 0` секунд; defaults −60 и 0,1. Эффективные значения возвращаются. Неверные параметры отклоняются до анализа. Sample тихий при `abs(x) ≤ 10^(T/20)`; равенство и ±0 включены. RMS, окна и гистерезис не применяются.

**R-06. Интервалы.** Выдаются максимальные непрерывные тихие серии каждого канала и серии frames, где одновременно тихие все каналы. Downmix запрещён. Интервал `[a,b)` содержит frames `a…b−1`; секунды равны `a/rate`, `b/rate`. Включаются серии длиной не менее `max(1,ceil(D·rate))` frames, включая начало/конец файла. Концы файла не объединяются. Общие серии определяются до фильтрации длительности, не пересечением отфильтрованных списков.

**R-07. NaN/Inf.** Чтение продолжается до EOF, насколько позволяет независимый отказ/отмена. По каждому каналу отдельно подсчитываются NaN, +Inf, −Inf и первые позиции: frame с нуля и время `frame/rate`; каналы индексируются с нуля в файловом порядке. Любое обнаружение означает диагностический отказ. Пики используют только конечные значения с явным ограничением области; при их отсутствии пик отсутствует. Нечисловой sample не считается тишиной, разрывает канальную и общую тихие серии. Полное чтение не означает полную определённость измерений.

**R-08. Целостность.** Проверяются RIFF-размер, границы/padding chunks, свойства формата, byte rate/block align, кратность frame и полное чтение data. Допускаются корректные неизвестные ancillary chunks; требуется один `fmt` перед одним `data`. Дубликаты, несогласованные размеры и неполные frames означают повреждение. Неподдерживаемый формат, недоступность и повреждение различаются. Заголовок или прочитанный префикс не доказывают успех. При прерывании сообщаются причина и обследованная область; незавершённая тихая серия не выдаётся завершённым интервалом.

**R-09. Пустой сигнал.** Корректный WAV с нулём frames успешно инспектируется: длительность 0, пики отсутствуют, интервалы пусты, счётчики NaN/Inf нулевые. Это отличается от повреждения и непустого нулевого сигнала.

**R-10. Результат.** Компактный JSON возвращается по умолчанию; status согласован с exit code. Различаются операция, вход, параметры, измерения, полнота сканирования/отчёта, предупреждения и ошибки. NaN/Infinity как JSON-числа запрещены; отсутствие измерения отличается от нуля. Успех требует полной допустимой инспекции и полного отчёта, но не соответствия художественным или validate-критериям. Тишина сама по себе не ошибка.

**R-11. Ограничения.** Аудио обрабатывается ограниченными порциями, без загрузки целиком и неконтролируемых allocations из заголовков. Численного SLA нет. Предел числа возвращаемых интервалов документируется и настраивается; точный счёт, порядок сохранения и default фиксирует дизайн. Превышение явно обозначает усечение и неуспешный исход, но сканирование, пики и счётчики продолжаются до EOF, кроме ошибки/отмены. Скрытая потеря интервалов недопустима; полнота сканирования не подменяет полноту отчёта.

**R-12. Безопасность.** Вход не изменяется, не исполняется, не ремонтируется; аудио, графики и обязательные долговременные audit-файлы не создаются. Чужие файлы/процессы неприкосновенны; shell-интерполяции нет. Не требуются SC, GUI, сеть, realtime-сервер, аудиоустройство или plotting-библиотеки; скрытых установок/настроек нет. Обнаруженное изменение входа означает неподтверждённый результат; универсальная защита от конкурентных подмен не обещается.

**R-13. Совместимость.** Условия успеха render, `scs-nrt-source/2`, опубликованный render JSON schema 2 и отказ nonfinite Buffer-ресурсов сохраняются. Контракт inspect версионируется по отдельному дизайну. Инструкция объясняет параметры, ограничения и отличие от validate. Проверяемая платформа — Linux; другие ОС требуют свидетельств.

### 4. Критерии приёмки

| ID | Условие → результат |
|---|---|
| AC-001 | Известные PCM16/float32 → правильные метаданные после полного чтения. |
| AC-002 | Неподдерживаемые представления → явный отказ без конверсии. |
| AC-003 | PCM16 −32768/+32767, float ±2 → корректные необрезанные пики; float-перегруз сам не ошибка. |
| AC-004 | Противофазные каналы → нет отмены пика или ложной общей тишины. |
| AC-005 | Defaults/явные настройки → значения отражены и применены. |
| AC-006 | Ниже/на/выше порога → правильная классификация; неверные параметры отклонены. |
| AC-007 | Пограничные длины и дробный `D·rate` → точные интервалы по R-06. |
| AC-008 | Разные канальные серии → правильная одновременная тишина без downmix. |
| AC-009 | NaN/±Inf, включая конец файла → полные счётчики/первые позиции, отказ. |
| AC-010 | Nonfinite между тихими samples → разрыв серий, ограниченные пики. |
| AC-011 | Усечение, дубликаты, неверные размеры/fmt → диагностируемое повреждение. |
| AC-012 | Ошибка чтения/отмена → честная обследованная область и неполнота. |
| AC-013 | Пустой и непустой нулевой сигналы → различимые результаты R-09. |
| AC-014 | Успех/значимые отказы → валидный JSON и согласованные status/code. |
| AC-015 | Превышение настроенного предела → усечение и отказ, но дальнейшие пики/счётчики до EOF. |
| AC-016 | Сложные пути/запрещённые входы → безопасная обработка без изменения файлов. |
| AC-017 | Linux без SC/GUI/сети/аудиоустройства → самостоятельный inspect работает. |
| AC-018 | Регрессии render → прежние контракты и результаты сохранены. |
