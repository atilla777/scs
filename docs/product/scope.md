# Цель, область и границы

[← Индекс](index.md)

## Цель и основной сценарий

Технический скилл `supercollider` позволяет агенту автономно пройти цепочку: **уточнить техническую задачу → найти нужный API в локальной документации → написать `.scd` → исполнить → исправить ошибки → отрендерить WAV (если требуется) → проверить результат → отдать артефакты и диагностику**.

Основной потребитель — AI-агент, умеющий работать с локальной файловой системой и командной строкой. Высокоуровневый музыкальный скилл и фабрика видео могут вызывать эту компетенцию, но не являются обязательными зависимостями.

## Принятые решения интервью

| № | Согласованное решение |
|---|---|
| D-01 | Полноценная техническая компетенция SuperCollider, а не исключительно WAV-экспорт |
| D-02 | Небольшая CLI-обёртка над штатными инструментами, не замена API |
| D-03 | Batch и управляемый интерактивный режим в целевой версии |
| D-04 | Краткие встроенные инструкции + локальная документация установленной версии |
| D-05 | Комплексная техническая диагностика программ и аудиофайлов |
| D-06 | Обнаружение расширений и контролируемые, согласованные изменения зависимостей |
| D-07 | Соответствие Agent Skills, приоритет Linux; без привязки к OpenCode |
| D-08 | Файловой структурой управляет вызывающий агент/проект |
| D-09 | CLI автоматизирует инфраструктурные операции, не конструирование музыки и синтезаторов |
| D-10 | Автотесты, seed, параметры рендеринга и сравнения с допусками |
| D-11 | Настройка ОС/пакетов только после разрешения пользователя |
| D-12 | Полезный MVP и последовательное расширение, без обязательного завершения всех возможностей сразу |
| D-13 | Компактный JSON по умолчанию, визуальные диагностические артефакты по запросу |

## Входит в целевой охват

- Язык `sclang`, классы, серверная модель SuperCollider; `SynthDef`, UGen, `Synth`, `Bus`, `Buffer`, `Group`.
- `Patterns`, `Events`, `Routine`, `Task`, `Clock`, программирование звуковых событий.
- Взаимодействие с `scsynth`, управление процессами и ресурсами, основы OSC.
- Независимые запуски, NRT-рендеринг, последующие интерактивные сессии.
- Поиск и чтение локальной справки; выявление установленных Quarks, библиотек классов и UGen-плагинов.
- Техническая проверка результатов, диаграммы по запросу, интеграционные тесты.

## Не входит

- Сочинение мелодий и гармоний, выбор художественного стиля, аранжировка, музыкальная оценка и мастеринг как творческая задача.
- Специализированная интеграция с Remotion, структура музыкального проекта, свои правила размещения медиа.
- Собственный музыкальный API вместо `sclang`, обязательные облачные сервисы, MCP, постоянный фоновый демон или GUI.
- Поддержка MIDI-контроллеров, внешнего оборудования и сложных интерактивных систем как обязательная функция.
- Автоматическая установка или обновление системных пакетов без явного согласования.
- Обязательные сторонние расширения и плагины для базовой функциональности.

## Основные принципы

1. **Разделение компетенций:** технический скилл знает, *как* реализовать требуемое звуковое поведение, но не выбирает *какое художественное поведение необходимо*.
2. **Стандарт прежде харнеса:** `SKILL.md` и его ресурсы совместимы с Agent Skills; OpenCode-специфичные механизмы не требуются.
3. **Штатный SuperCollider:** использовать его API напрямую; обёртка закрывает только повторяемые инфраструктурные операции.
4. **Прозрачность и отсутствие ложного успеха:** запуск процесса или появление файла сами по себе не означают успешное выполнение.
5. **Headless по возможности:** NRT не зависит от физического аудиовыхода; для realtime чётко документировать требования к аудиобэкенду.
6. **Нет навязанной файловой структуры:** входы, выходы и временные каталоги определяются явно или по контексту вызывающего проекта.
