# Этапы реализации и критерии приёмки

[← Индекс](index.md)

## MVP — достаточная техническая основа для автономного создания аудио

Должны быть реализованы `FR-01`–`FR-09` и применимые `NFR-*`; `FR-12` действует как политика любого изменения окружения. В MVP требуется визуализация по запросу, но она может зависеть от явно обозначенной опциональной локальной библиотеки. Отсутствие такой библиотеки должно приводить к корректному отказу **только** команды построения графика.

**Главный сквозной сценарий:** агент получает техническое задание, находит локальную справку, создаёт `.scd` на основе корректного NRT-контракта, исправляет ошибки, рендерит WAV без GUI и физического аудиоинтерфейса, проверяет его и возвращает готовые файлы с диагностикой.

## После MVP — полная техническая компетенция

- `FR-10`: управляемая постоянная интерактивная сессия с сохранением состояния.
- `FR-11`: расширенная работа с Quarks/UGen и проверка совместимости.
- Совершенствование диагностики, очистки ресурсов и восстановления после ошибок.

## Следующий этап переносимости

Практическая валидация macOS, Windows и дополнительных харнесов; кроссплатформенные интеграционные тесты. Linux остаётся исходной проверенной платформой.

## Критерии после MVP

- Сессия сохраняет переменные между двумя отдельными `eval`, завершается по запросу и корректно сообщает о падении процесса (`FR-10`).
- Скилл распознаёт наличие/отсутствие тестового Quark/UGen и не устанавливает расширения без разрешения (`FR-11`).
- Кроссплатформенность заявляется лишь по результатам исполнения соответствующих тестов на целевой ОС.

## Открытые инженерные решения, НЕ требующие нового продуктового интервью

1. Язык реализации тонкого CLI и библиотеки для аудиоинспекции и построения графиков.
2. Способ обнаружения исходников HelpSource/локальных документов установленного пакета; поведение при их отсутствии.
3. Надёжный протокол завершения `sclang`, не полагающийся только на код возврата процесса.
4. Устройство NRT-контракта `.scd` и минимального тестового шаблона, передача параметров рендеринга.
5. Конкретная схема JSON, кодов ошибок и тестовых фикстур при соблюдении публичных контрактов.

Не добавлять без необходимости собственный движок синтеза, специализированную музыкальную DSL, MCP-сервис или обязательную контейнерную среду.
