# Нефункциональные требования и контракты

[← Индекс](index.md)

### NFR-01. Переносимость
Скилл следует спецификации Agent Skills, не требует OpenCode-specific hooks. Linux (Omarchy/Arch) — обязательная проверяемая платформа MVP. Архитектура не должна препятствовать macOS/Windows и другим совместимым харнесам; их полноценная поддержка — отдельный этап. Не зашивать абсолютные пути и конкретный shell без необходимости.

### NFR-02. Безопасность файлов
Исходники и выходы задаёт вызывающий агент; скилл не навязывает структуру проекта. Абсолютные и относительные пути допустимы. Не перезаписывать существующие пользовательские файлы без явного разрешения. Временные данные изолировать по запускам и безопасно очищать; при ошибках сохранять полезную диагностику, не трогая чужие файлы.

### NFR-03. Надёжность исполнения
Учитывать возможное зависание/долгую жизнь `sclang`. Вводить ограничиваемые тайм-ауты, корректное завершение контролируемых процессов, обработку stdout/stderr, явный критерий успеха. Не объявлять успех на основании одного exit code или появления файла. Исключить небезопасную интерполяцию shell-аргументов.

### NFR-04. Машиночитаемые результаты
CLI возвращает предсказуемые коды завершения и компактный JSON по запросу. Вывод должен различать `status`, тип операции, артефакты, диагностику/предупреждения/ошибки, существенные параметры и версии окружения. Непосредственный формат JSON уточняется на проектировании; ошибки должны быть достаточны для самостоятельного исправления агентом.

### NFR-05. Воспроизводимость
Шаблоны поддерживают управляемые random seed и фиксированные параметры NRT. При необходимости фиксируются версии SuperCollider/расширений и параметры файла. Тесты сравнивают свойства и звуковые метрики с допусками. Побитовая идентичность между платформами не гарантируется.

### NFR-06. Локальность и зависимости
Повседневная работа не требует интернета, облачного сервиса, MCP или GUI. Стандартный SuperCollider достаточен для базовой работы. Необязательные библиотеки диагностики и расширения не должны бесконтрольно устанавливаться или делать все команды недоступными.

### NFR-07. Минимальный контекст агента
`SKILL.md` — краткая точка входа и правила выбора операций; `references/` содержит подробности и открывается по необходимости; `assets/` — только полезные проверенные примеры. Не включать копию всей документации SuperCollider. Избегать повторений и собственной DSL для синтеза.

### NFR-08. Граница объективной диагностики
Инструмент сообщает измеренные свойства сигнала и технические предупреждения, но не качество композиции. Визуализации — необязательные диагностические артефакты, не обязательный вывод каждой операции.

### NFR-09. Контроль системных изменений
Перед установкой/изменением системного компонента требовать согласование конкретного плана. Никаких скрытых обновлений, удаления пакетов или изменения глобальной конфигурации при `run`/`render`.

## Логический контракт операций

**Вход:** явная программа или аудиофайл, необходимые параметры, пути и допуски.

**Выход:** статус и диагностические сведения; при успехе — заявленный артефакт и проверяемые параметры; при ошибке — стадия сбоя и действия для исправления.

**Отказы:** различать неверный вход, отсутствие компонентов, сбой `sclang`, ошибку NRT/`scsynth`, тайм-аут, недопустимый/неполный аудиофайл и отсутствие необязательных средств визуализации.

**Ресурсы:** каждая операция должна завершать только принадлежащие ей процессы, не затрагивать чужие сессии и сохранять предсказуемое состояние файловой системы.
